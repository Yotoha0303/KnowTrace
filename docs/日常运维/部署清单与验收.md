### ① 备份链从未建立 —— 这台机器目前没有任何可用备份

**证据**：`/var/backups/knowtrace/` 不存在；`knowtrace_backup_archive_count = 0`；

**动作**（注意：备份会**短暂停止 app/auth 写入**，有用户时先公告）：

```bash

scripts/linux/backup-all.sh                       # 产出归档

scripts/linux/verify-restore.sh /var/backups/knowtrace/<归档>   # 隔离恢复验证，不碰生产
```

**完成标准**：归档存在 **且** 隔离恢复验证 PASS。
**未经恢复验证的备份不能算备份。**

顺带这一项会同时消掉：周巡检的 `backup.root` FAIL、月巡检的 `drill.backup` /
`prune.root` / `apply.drill` FAIL（共 3 条 FAIL 同源）。

### ② 外地备份未配置

需要先决定后端（S3 / Cloudflare R2 / …），再写 `/etc/knowtrace/age-recipient.pub`
与 `OFFSITE_REMOTE`。**age 私钥只应存在你的密码管理器/离线介质，不在服务器上。**

参考：仓库外 `KnowTrace-ops/docs/2026-09-29-异地备份实施记录与剩余步骤.md`

### ③ `AUTH_COOKIE_SECURE=false` —— HTTPS 部署下必须是 `true`

**证据**：`docker exec knowtrace-workflow-app-1 printenv AUTH_COOKIE_SECURE` → `false`；
安全巡检直接判 FAIL（`env.auth-cookie-secure`）。

含义：会话 Cookie **没有 `Secure` 标志**，浏览器可能通过明文 HTTP 发送它。
站点已经在 HTTPS 上（Caddy + Let's Encrypt），所以这一项**该开**。

> ⚠️ 改动前**必须**先确认：链路是 `Caddy(HTTPS) → nginx → app`，
> app 侧看到的是 HTTP。若设成 `true` 而 Cookie 被判定为非安全上下文，
> **会导致登录态失效**。所以这不是「改个变量就完事」，要连着验证登录/刷新一起做。
> 另外 `AUTH_COOKIE_SECURE` 目前**不在** Git 里（属运行时配置），改完记得纳入备份范围。
