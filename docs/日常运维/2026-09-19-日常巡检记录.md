## 本次已执行操作

### 文件与目录检查

- 使用 `ls -la` 检查服务器上的文件和目录内容。
- 目的：确认项目目录、配置文件、脚本、数据目录或部署相关文件是否存在异常缺失、权限异常或误删迹象。
- 后续建议：下次巡检时保存关键目录的输出，例如项目根目录、部署目录、日志目录、备份目录和上传目录。

### 主机资源检查

- 使用 `htop` 查看机器资源使用情况。
- 关注点：
  - CPU 是否长期高占用。
  - 内存和 Swap 是否接近耗尽。
  - 是否存在异常进程、僵尸进程或长期占用资源的服务。
  - Elasticsearch、Kibana、数据库、Node.js、Go 服务等进程是否符合预期。
- 后续建议：补充 `free -h`、`df -h`、`uptime` 作为可复制的文本证据。

### 容器状态检查

- 使用 `docker ps` 查看运行中的容器。
- 目的：确认 KnowTrace 应用、数据库、认证服务、缓存、监控组件和日志组件是否处于预期运行状态。
- 关注点：
  - 容器是否频繁重启。
  - 端口映射是否符合预期。
  - 不需要常驻的高资源容器是否仍在运行。
  - Elasticsearch、Kibana 是否按需启动，而不是在资源紧张时长期占用内存。

### 本地端口转发与监控访问

- 在本地使用 `ssh -N -L` 建立端口转发。
- 本次涉及端口：
  - `9090`：Prometheus
  - `3000`：Grafana 或应用访问端口，具体以当时转发目标为准
  - `3001`：Grafana 或其他监控访问端口，具体以当时转发目标为准
- 目的：在不直接暴露监控端口到公网的情况下，从本地浏览器访问远程监控页面。
- 已查看：
  - Prometheus
  - Grafana
- 后续建议：记录每个本地端口对应的远程目标，例如 `127.0.0.1:9090 -> 远程 127.0.0.1:9090`，避免后续排障时混淆应用端口和监控端口。

### 停止高资源日志组件

- 使用 `docker stop` 停止了 Elasticsearch 和 Kibana 容器。
- 原因：ELK 组件资源占用较高，更适合作为按需实验组件，不适合在小规格 VPS 上长期常驻。
- 影响：
  - 停止后无法继续实时查看 Kibana 页面。
  - Elasticsearch 内的日志检索能力暂时不可用。
  - 不影响 KnowTrace 主应用、数据库、Prometheus 和 Grafana 的基础运行，前提是这些服务没有依赖 Elasticsearch。
- 后续建议：
  - 保留 ELK 的 Compose 配置和启动说明。
  - 需要日志检索实验时再临时启动。
  - 如果未来要做生产级日志，应优先考虑资源限制、日志保留周期和磁盘告警。

### 处理 Xshell 访问机器过慢

- 本次处理了 Xshell 访问远程服务器过慢的问题。
- 常见原因方向：
  - SSH DNS 反查导致登录慢。
  - GSSAPI 认证等待导致连接慢。
  - 本地网络或代理链路不稳定。
  - 服务器负载高，导致 shell 响应慢。
  - 终端启动脚本执行了耗时命令。
- 后续建议：
  - 记录最终采用的处理动作。
  - 若修改了 SSH 服务端配置，应记录原值、修改值、重载命令和回滚方法。
  - 若只是客户端配置或网络调整，也应记录具体调整点。
