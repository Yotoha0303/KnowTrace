# 2026-09-19 运维回顾

## 定位

本次运维属于 KnowTrace 单机 VPS / Docker Compose 环境下的日常巡检、资源治理和访问问题处理。

当前项目已经具备基础可运维条件：有容器化部署、健康检查、备份恢复脚本、Prometheus/Grafana 监控、ELK 按需日志实验、日常巡检清单和故障记录习惯。但它仍处于个人项目的运维实践阶段，不能直接表述为完整生产级高可用系统。

## 运维职责

本项目运维职责主要包括：

- 保障 KnowTrace 主应用、认证服务、数据库、缓存和监控组件处于可访问、可恢复、可观察状态。
- 定期检查服务器资源，及时发现 CPU、内存、Swap、磁盘和异常进程风险。
- 检查 Docker 容器运行状态，识别异常重启、端口异常、资源占用过高和非必要常驻组件。
- 通过 SSH 隧道安全访问 Prometheus、Grafana 等管理页面，避免把监控端口直接暴露到公网。
- 对高资源组件采用按需启动策略，尤其是 Elasticsearch 和 Kibana。
- 保留巡检、故障、变更、备份和恢复验证记录，为后续排障、复盘和面试陈述提供证据。

## 运维目的

本次运维的目的不是单纯“看看机器还在不在”，而是确认项目是否具备持续运行和后续排障的基本条件。

具体目标：

- 确认服务器文件、目录和部署环境没有明显异常。
- 观察主机资源使用情况，判断是否存在资源瓶颈。
- 确认容器运行状态，识别不必要的资源占用。
- 通过本地端口转发访问 Prometheus 和 Grafana，验证监控入口可用。
- 停止暂不需要常驻的 Elasticsearch 和 Kibana，降低小规格 VPS 的资源压力。
- 处理 Xshell 访问远程机器过慢的问题，改善日常管理效率。
- 将本次操作沉淀为可复用的日常运维 SOP 和复盘材料。

## 标准 SOP

### 1. 登录与环境确认

- 确认当前连接的是目标服务器。
- 确认当前用户、当前目录和项目路径。
- 检查系统运行时间、负载、内存、Swap 和磁盘。
- 不在未确认机器、未确认目录下执行停止、删除、覆盖或重启操作。

参考命令：

```bash
hostname
whoami
pwd
uptime
free -h
df -h
```

### 2. 文件与目录巡检

- 使用 `ls -la` 查看项目目录、部署目录、备份目录、日志目录和上传目录。
- 检查是否存在权限异常、误删、异常大文件或临时文件堆积。
- 不在巡检记录中保存密钥、Token、Cookie、完整 `.env` 或真实用户敏感内容。

### 3. 主机资源巡检

- 使用 `htop` 或等价命令查看 CPU、内存、Swap 和进程状态。
- 关注 Node.js、数据库、Go 认证服务、Docker、Elasticsearch、Kibana 等进程。
- 如果资源紧张，优先判断是否由 ELK、构建任务、日志堆积或数据库压力引起。

### 4. Docker 容器巡检

- 使用 `docker ps` 查看运行中容器。
- 检查 KnowTrace、PostgreSQL、MySQL、Redis、认证服务、Prometheus、Grafana 是否符合预期。
- 检查容器是否出现频繁重启。
- 查看关键容器最近日志，优先关注 error、warn、timeout、connection refused、permission denied。
- 禁止把 `docker compose down -v` 当作普通排障命令，避免误删数据卷。

### 5. 监控访问

- 使用 `ssh -N -L` 从本地转发 Prometheus 和 Grafana 端口。
- 检查 Prometheus Targets、Alerts、Grafana 数据源和核心仪表盘。
- 记录本地端口和远程目标端口的对应关系，避免排障时混淆。
- 监控页面不直接暴露公网。

### 6. 日志组件治理

- Elasticsearch 和 Kibana 在小规格 VPS 上按需启动。
- 启动前检查内存和磁盘。
- 使用后如无持续实验需求，应及时停止。
- 停止前确认不会影响主应用、数据库、Prometheus 和 Grafana 的核心运行。

### 7. 故障处理与记录

- 故障处理前先保存现象和证据。
- 区分事实、推断和未知。
- 修改配置时记录原值、修改值、重载命令和回滚方法。
- 处理后必须做恢复验证。
- 每次故障至少记录：时间、现象、影响范围、排查命令、关键证据、处理动作、验证结果、遗留风险。

## 结论

本次运维不是简单检查，而是一次基础日常巡检、资源治理和访问问题处理。

从能力建设角度看，本项目已经具备基础可运维骨架：能部署、能检查、能看监控、能做备份恢复设计、能记录故障和巡检。但距离规范化生产运维还需要补齐证据留存、周期化巡检、自动告警闭环、恢复演练验收、容量基线和发布回滚 SOP。
