**1. 备份与恢复**
说明：这里的核心不是“有备份文件”，而是证明“真的能恢复”。

操作步骤：

```bash
cd /opt/knowtrace

docker compose -f compose.yaml -f compose.production.yaml ps
sudo ls -lh /var/backups/knowtrace
sudo ls -lh /var/backups/knowtrace/*.sha256
```

如果要生成一次新备份：

```bash
sudo BACKUP_ROOT=/var/backups/knowtrace \
  /opt/knowtrace/scripts/linux/backup-all.sh \
  | sudo tee /var/log/knowtrace-backup-last.log
```

然后找最新备份做隔离恢复验证：

```bash
archive=/var/backups/knowtrace/knowtrace-具体文件名.tar.gz

sudo /opt/knowtrace/scripts/linux/verify-restore.sh "$archive" \
  | sudo tee /var/log/knowtrace-restore-check-last.log
```

只看到 `RESTORE_VERIFY=PASS`，才可以写“隔离恢复验证通过”。

注意：这个验证不是恢复生产数据库，而是在临时容器里恢复检查，比较安全。真正恢复生产库属于高风险操作，不要随便做。

最后还要做业务验证：

```text
能打开登录页
能登录
能查看历史记录
能读取附件
能保存一条非敏感测试记录
```

**2. 安全与访问**
这里先做只读检查，不要一上来改 SSH、防火墙或服务配置。

检查 SSH 登录方式：

```bash
sudo sshd -T | grep -Ei 'pubkeyauthentication|passwordauthentication|permitrootlogin|usedns|gssapi'
```

看最近登录和失败登录：

```bash
last -a | head -n 20
sudo journalctl -u ssh --since today --no-pager
```

看公网暴露端口：

```bash
sudo ss -tulpen
sudo ufw status verbose
docker ps --format 'table {{.Names}}\t{{.Ports}}\t{{.Status}}'
```

看 Nginx/Caddy 是否有大量异常请求：

```bash
sudo tail -n 200 /var/log/nginx/access.log
sudo tail -n 200 /var/log/nginx/error.log
```

如果你要检查默认密码是否更换，只检查“是否仍使用默认值”，不要把真实密码写进文档：

```bash
sudo grep -nE 'PASSWORD|SECRET|TOKEN|KEY' /opt/knowtrace/.env
```

记录时写：

```text
已检查生产 .env 中关键密码项，未在文档中保存明文值。
```

注意：不要把 `.env` 内容复制到 Markdown。

**3. 发布与变更**
发布前先做这几个确认：

```bash
cd /opt/knowtrace

git status --short
git rev-parse --short HEAD
git log -1 --oneline
docker compose -f compose.yaml -f compose.production.yaml ps
curl -fsS http://127.0.0.1:3000/api/health/ready
```

发布前必须确认有可用备份：

```bash
sudo ls -lh /var/backups/knowtrace | tail
```

发布后检查：

```bash
docker compose -f compose.yaml -f compose.production.yaml ps
curl -fsS http://127.0.0.1:3000/api/health/live
curl -fsS http://127.0.0.1:3000/api/health/ready
docker compose -f compose.yaml -f compose.production.yaml logs --tail=100 app
```

浏览器里再检查：

```text
登录页
登录
记录列表
记录详情
保存一条测试记录
Prometheus Targets
Grafana 仪表盘
```

失败时不要立刻乱删容器。先保存日志：

```bash
docker compose -f compose.yaml -f compose.production.yaml logs --tail=300 app auth postgres auth-mysql redis
```

特别注意：不要把 `docker compose down -v` 当成普通回滚命令，它可能删除数据卷。
