# 暂缓问题与后续迭代清单

本文件记录已经明确提出、但当前迭代暂不处理的问题。这里的“当前现象”来自使用者报告，不等于已经通过日志、测试或代码复现；进入开发迭代后必须先复现，再实现和验收。

## KT-DEFER-001 无实际修改仍重复保存 Revision

状态：已完成。服务端在乐观锁校验后比较规范化持久化字段；无变化时不更新 Capture、不增加版本、不创建 Revision，分类关系单独判断。

当前现象：同一版本的记录即使标题、正文、内容类型、描述对象、发生时间等有效内容没有变化，重复点击保存仍可能增加版本号或历史记录。

期望行为：保存前比较规范化后的持久化字段；没有实际变化时不更新 Capture、不增加版本号、不创建 Revision，并向用户提示“没有需要保存的修改”。分类等独立关系的变化应按各自规则处理，不能错误生成正文 Revision。

后续验收：

- 连续多次提交完全相同的数据，Capture 版本和 Revision 数量保持不变。
- 仅存在空白、日期格式等可规范化差异时，不产生虚假版本。
- 任一受版本管理字段真正变化时，只增加一个版本并保存一个正确的历史快照。
- 乐观锁和并发冲突检查继续有效，不能用“无变化”判断绕过并发保护。

## KT-DEFER-002 AI 整理前反复要求测试连接

状态：已完成。选择 CC-Switch 后自动检测代理、供应商和可用路由；检测到可用路由即可直接运行，模型测试保留为可选排障入口。

当前现象：已经成功使用过的 CC-Switch 连接，在后续 AI 整理或分析前仍反复要求用户手动点击“测试当前供应商”，无法直接运行。

期望行为：选择 CC-Switch 后自动完成必要的代理、供应商和模型能力检查；成功状态在合理范围内复用，使用户进入已配置环境后可以直接运行 AI。不能把每次 AI 操作都变成一次重复的手工连接测试。

后续验收：

- 同一浏览器会话、同一 CC-Switch 地址、供应商和模型配置在测试成功后，后续整理与分析可以直接运行。
- 页面刷新或在记录之间切换不会无条件清除仍然有效的成功状态。
- CC-Switch 供应商、模型、地址或凭据发生变化，或者实际调用返回连接/鉴权/模型错误时，旧状态必须失效并自动重新检测。
- 检测过程展示明确状态和失败原因，不使用无限加载动画，也不要求用户反复手动测试。
- 缓存的“可用”状态不能掩盖 CC-Switch 已停止或已切换供应商的事实。

## KT-DEFER-003 管理员创建内容对成员可见

状态：已完成。管理员新建和导入的 Capture 默认 `shared`，普通成员新建和导入默认 `private`；共享内容对普通成员只读。管理员首次访问时会把本人历史私有记录迁移为共享，迁移脚本同时覆盖本地管理员和默认首个管理员标识。

当前现象：管理员可以读取所有成员的内容，但管理员自己创建的记录仍按创建者私有范围处理，其他管理员和普通成员无法看到。

期望行为：管理员账户创建的内容可以作为小群体共享内容，被其他已登录管理员和普通成员查看；普通成员自行创建的内容仍只对本人和管理员可见，不得因此变成成员之间互相可见。

后续验收：

- 管理员 A 创建的共享记录，管理员 B 和普通成员均可读取，并能在允许的列表、检索、分类和对象时间线中找到。
- 普通成员 A 创建的私有记录对普通成员 B 仍不可见。
- 管理员仍能按管理权限查看所有成员内容。
- 详情、搜索、分类、图片、导入导出和派生知识使用同一可见性规则，不能只修复首页列表。
- 下一迭代必须明确管理员内容是默认共享还是由管理员显式选择，并决定现有管理员记录是否需要迁移；在决定前不批量改变历史数据权限。

## KT-DEFER-004 同一用户可重复导入相同记录

状态：已完成防重，仍不自动删除既有重复数据。导入使用“创建者 + v1 记录指纹”并保留稳定记录标识检查；数据库部分唯一索引防止并发重复写入。

当前现象：同一用户可以重复导入相同文件或相同记录，系统会再次创建 Capture，导致重复记录持续增加。

期望行为：导入以“用户身份 + 来源记录身份”为隔离边界进行幂等判断。同一用户重复导入同一来源记录时跳过重复项；不同用户导入相同内容仍分别属于各自数据，不能跨用户错误去重。

后续验收：

- 优先使用导出文件中的稳定记录 ID、版本或导入来源 ID 识别同一记录。
- 缺少稳定 ID 时，使用经过明确定义和版本化的记录指纹；指纹字段必须包含创建者范围，并避免把内容相同但事件时间或描述对象不同的合法记录误判为重复。
- 同一文件内的重复行和跨多次导入的重复记录都能识别。
- 导入预览和结果明确显示新增、跳过重复、冲突和失败数量，并允许查看原因。
- 防重检查和写入必须在数据库层保持并发安全，不能只依赖前端筛选。
- 对已经存在的重复记录，后续提供只读扫描和合并/删除预览；任何清理必须再次确认，不在本次记录工作中执行。
