# 风险清单

## 1. 产品风险

### R-01 AI 功能再次扩展成完整验证闭环

- 影响：首版无法交付。
- 应对：AI 整理、Claim/Evidence、来源权威性、跨身份复核和可靠发布均是边界明确的纵向切片；自动联网补证、永久真实性声明和公网分发继续延期。

### R-02 分类体系过度设计

- 影响：用户在记录前花费大量时间选目录。
- 应对：Content Type 固定单选；Category 扁平多选；允许零分类保存。

### R-03 把普通记录误称为可靠知识

- 影响：用户错误信任未经验证内容。
- 应对：Capture 只有 active/archived；AI confidence 不展示为真实性评分。

## 2. 认证与共享数据域风险

### R-04 应用被直接暴露到公网

- 影响：任何访问者都能读取和修改全部数据。
- 应对：默认仅本机/可信网络；可选接入 go-user-system；公网仍必须配置 HTTPS、安全 Cookie、网络隔离和运维监控。

### R-05 小群体无法可靠归因

- 影响：不知道谁进行了编辑或分类。
- 应对：只信任服务端验证的 go-user-system 身份；可靠发布阶段增加 actor/reviewer 审计和职责分离，之前不声称已经归因。

### R-06 用户误以为记录私密

- 影响：小组共享部署中泄露个人内容。
- 应对：Capture/Category 保存创建者；普通成员的列表、详情、搜索、导入导出、派生知识与图片访问统一按创建者过滤，管理员例外；新增端点必须复用服务端数据访问层。

### R-06A 认证服务不可用或被绕过

- 影响：合法使用者无法访问，或未认证请求读取私人记录和证据图片。
- 应对：Proxy、Server Action 与私有 Route Handler 分层校验；上游异常 fail closed；保留健康检查和短超时，不以认证失败回退匿名模式。

## 3. 数据风险

### R-07 AI 覆盖原文

- 影响：来源丢失，无法追溯。
- 应对：Suggestion 分表；接受建议也不得更新正文。

### R-08 并发编辑覆盖

- 影响：小群体使用时丢失内容。
- 应对：expectedVersion 乐观锁和 Revision。

### R-09 网络重试产生重复记录

- 影响：出现重复 Capture。
- 应对：幂等键和请求体一致性检查。

### R-10 Category 失控增长

- 影响：大量同义、大小写或空白差异分类。
- 应对：规范化名称唯一；AI 新分类必须人工接受；后续根据真实数据增加合并功能。

## 4. AI 风险

### R-11 Prompt 注入

- 影响：输入内容诱导模型偏离结构化任务。
- 应对：输入作为不可信数据；P0 不提供工具；Schema 和来源片段校验。

### R-12 供应商格式差异

- 影响：简单替换 Base URL 后运行行为不一致。
- 应对：独立 Provider Adapter 和契约测试。

### R-13 长请求中断

- 影响：Run 停留 running，用户不知道结果。
- 应对：总超时、Run 清理；达到触发条件后迁移 Worker。

### R-14 费用失控

- 影响：重复运行、超长输入或使用高成本模型。
- 应对：主动触发、字符限制、模型白名单、用量记录和每日软限额。

### R-15 模型添加原文不存在的信息

- 影响：AI 建议污染分类和语义结果。
- 应对：source_excerpt 定位、unsupported 标记、人工接受。

### R-16 来源检查触发 SSRF

- 影响：恶意 URL 可能访问本机、数据库、云元数据或可信内网服务。
- 应对：只允许标准端口 HTTP(S)；拒绝 URL 凭据、本机/私网/保留地址；DNS 结果全部校验并把请求固定到已校验 IP；每次重定向重新校验；限制响应头、响应体、类型、次数和超时。

### R-17 把“摘录匹配”误认为“来源可靠”

- 影响：页面确有这句话，但页面本身不权威或主张仍然错误。
- 应对：UI 明确来源检查只证明当时可访问与摘录存在；不生成真实性分数，不自动采纳，不提供 verified 状态。

### R-18 把 AI 可靠性建议误认为最终裁决

- 影响：模型基于有限或单一证据给出的倾向被当成事实结论。
- 应对：只输入已确认采纳证据快照；服务端重算覆盖和平衡、过滤伪造 Evidence ID、覆盖固定边界提示；UI 使用“AI 建议”并禁止写入 Review 或状态；输入变化后标记旧结果过期。

## 5. 技术风险

### R-19 元框架追求“最新”导致使用 Preview

- 影响：API 变化、安全修复和第三方兼容问题。
- 应对：使用最新稳定/LTS 补丁，不把 Preview/Canary 当生产默认。

### R-20 Server Action 承担过多业务逻辑

- 影响：代码难测试，未来无法复用到 App API。
- 应对：Server Action 与 `/api/v1` Route Handler 只做输入适配，规则放 Application Service；移动端接口复用同一乐观锁、幂等和删除策略。

### R-20 复用 GitHub 项目带入无关复杂度

- 影响：删除认证、租户、计费逻辑比重新开始更困难。
- 应对：M0 做限时适配评估；只移植匹配模块。

### R-21 单实例数据库迁移失误

- 影响：个人积累数据丢失。
- 应对：Migration 只追加；升级前备份；发布前恢复演练。

### R-22 CC-Switch 路由可用被误认为供应商已识别

- 影响：界面显示通用或错误的供应商名称；用户在 CC-Switch 切换到 DeepSeek、Codex 或其他模型后，无法确认本次 AI Run 实际由谁处理。
- 应对：下一迭代把代理健康、供应商身份和模型能力拆成独立检测结果；供应商身份必须来自可信元数据或可验证的 CC-Switch 接口，不能根据可映射的模型别名猜测；未知时明确显示“未识别”。

## 6. 复查节奏

- 每个里程碑结束复查。
- 改变部署边界、AI Provider 或数据模型时立即复查。
- 出现私人内容隔离或成员审计需求时，将 Workspace 授权与操作者审计提升为阻断风险；不能把“已登录”等同于“已隔离、已审计”。
