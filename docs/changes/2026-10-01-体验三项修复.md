## 1. 本次要修的三件事

### 1.1 D-03 会话过期被显示成「数据库未启动」（P0）

**用户报告的原始现象**：「AI 修改后，过一段时间点击保存，提示找不到数据库」。

**根因链**【依据：服务器 `INC-009` 报告，本次复核一致】：

| # | 环节 | 位置 |
| --- | --- | --- |
| 1 | Access Token 有效期 15 分钟 | `go-user-system` 配置 |
| 2 | **应用主界面无会话续期**——只在登录页组件加载时刷新一次 | `src/components/login-form.tsx:33` |
| 3 | Proxy 只验 Access Token，过期后**不尝试 Refresh Token** | `src/proxy.ts:98-125` |
| 4 | 非 API 请求统一 **307 重定向到登录页 HTML** | `src/proxy.ts:23-29,118-125` |
| 5 | Server Action 收到 HTML 而非结构化结果，解析失败 | — |
| 6 | 全局错误边界把所有异常**固定显示成「请确认数据库已经启动」** | `src/app/error.tsx:6` |

**第 6 条是伤害最大的一环**：真实原因是会话过期，用户看到的是数据库故障——
**会让用户怀疑数据还在不在**。

**改动方案**：

| 改动 | 内容 |
| --- | --- |
| a | `error.tsx` 文案改为中性，且**按 digest/类型区分**：会话类错误提示重新登录，其余提示重试；**不再断言是数据库问题** |
| b | `proxy.ts`：Cookie 客户端 Access Token 失效时，**先尝试用 Refresh Token 换新**；成功则放行并下发新 Cookie，失败才走未认证分支 |
| c | 非 API、非导航的请求（Server Action）**不再 307 成 HTML**，改为可被识别为认证失效的响应 |
| d | 两条回归测试进 `src/proxy.test.ts` |

**验收（可判定）**：
- 页面开着超过 15 分钟后点保存 → **自动续期成功**，不出现错误页；
- Refresh Token 也失效时 → 明确提示「登录已过期，请重新登录」，**不出现「数据库」字样**；
- 两条测试在 CI 中运行。

**不做什么**：
- **不做客户端定时续期**——那是把服务端该做的事推给浏览器，且多标签页/休眠下不可靠。续期应由 Proxy 在令牌失效时按需触发。

### 1.2 静态资源无长缓存（"访问慢"的真实成因）

**已实测的归因**（`docs/19` D-04，本次复核一致）：

| 事实 | 值 |
| --- | --- |
| 服务端 p50 / max | **5.9 ms / 607 ms**（**无一条超 1 秒**） |
| 浏览器侧 JS | **1.2 MB / 24 chunk**，最大单块 283 KB |
| `/_next/static/*` 响应头 | `private, no-cache, no-store` ← **可指纹化却未长缓存** |

**改动方案**：在 `next.config.ts` 为 `/_next/static/*` 配置
`Cache-Control: public, max-age=31536000, immutable`。

**为什么安全**：Next 的 `/_next/static/` 路径**带内容哈希**，内容变则路径变，
因此长缓存不会读到旧版本。**这是标准做法，不是"关掉缓存"。**

**验收**：`curl -I` 对 `/_next/static/` 下任一资源返回 `immutable`。

**不做**：不动 HTML 与 API 的缓存（那些是 `no-store`，**正确**）。

### 1.3 「使用快捷键」文档声称有、实现没有

**实测**：`grep -rn "ctrlKey|metaKey|Ctrl+Enter" src/components/ src/app/` → **空**，
而 `docs/02-user-flows.md:20` 写着「点击保存/**使用快捷键**」。

**改动方案**：给 `QuickCaptureForm` 加 `Ctrl/Cmd + Enter` 提交。
**这是"记录优先"产品最该有的省力机制**，而且成本极低。

**验收**：快速记录框内按 `Ctrl/Cmd + Enter` 即保存，与点保存按钮等效。

**理由（为什么是改代码而不是改文档）**：这是记录产品的核心动作，
一个快捷键能显著降低单次记录成本；而且产品原则第 1 条是"先保存，后整理"，
**入口越省力越符合定位**。
