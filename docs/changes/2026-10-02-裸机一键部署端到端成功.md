## 3. 第 8 个缺陷特别值得记：我的修复只修了一半

**现象**：端到端退出码 0、一切正常，但 `verify` 的警告说：

```text
[WARN] 管理员口令是固定值 KnowTrace@123 —— 公网可达时**必须**改
```

**实测该口令从公网登录返回 200** —— 一个口令写在公开 README 里的站点上了线。

**根因**：我上一轮改了 `init-env` 让口令默认随机，判据是「值为空才生成」；
但 **`.env.example` 里写的是非空字面量 `KnowTrace@123`**，判据**永不触发**。

> **我当初测试用的是"空值"场景，而真实路径根本不是空值。**
> 命令返回 0 不算验收 —— 部署退出码 0，却产出了一个公网可登录的固定口令站点。

**修法**：`.env.example` 里留空。隔离验证：新的 `.env.example` + `init-env`
→ 生成 **32 字符随机口令**（不再是固定值）。

**应急处置**：在目标机上 API 轮换（新口令 200 / 旧口令 401），
凭据写入 `/root/knowtrace-admin-credential.txt`（600），`.env` 同步。
