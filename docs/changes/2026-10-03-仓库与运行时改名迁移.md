## 4. 【必做】数据库与数据卷 —— 不做会起不来

> 背景：`POSTGRES_DB` / `POSTGRES_USER` 只在**卷首次初始化**时生效；卷里已有旧库旧用户时，
> 改这两个环境变量**不会有任何效果**，应用会去连一个不存在的库/用户而失败。

**方案 A（推荐，零搬迁、零停机风险）**：数据卷沿用旧名。

- 在服务器 `compose.yaml` 里给新卷键显式钉住旧实际卷名（与本仓库既有的
  `auth_mysql_data: name: go-user-system_mysql_data` 写法一致）：
  ```yaml
  volumes:
    knowtrace_workflow_postgres18:
      name: knowtrace_postgres18   # 指向既有卷，数据原地保留
  ```
- 库名/用户改名（应用连接串已改为 `knowtrace_workflow`）：
  ```bash
  docker exec -it knowtrace-postgres-1 psql -U knowtrace -d postgres -c \
    'ALTER DATABASE knowtrace RENAME TO knowtrace_workflow;'
  docker exec -it knowtrace-postgres-1 psql -U knowtrace -d postgres -c \
    'ALTER USER knowtrace RENAME TO knowtrace_workflow;'
  ```
  （改名后旧名登录失效，属预期。）
- 服务器 `.env`（**不在 git 内，必须手改**）里的 `DATABASE_URL` 同步改为新库/新用户。

**方案 B（真正把卷也改名，需一次停机拷贝）**：

```bash
docker compose -f compose.yaml -f compose.production.yaml down
docker volume create knowtrace_workflow_postgres18
docker run --rm -v knowtrace_postgres18:/from -v knowtrace_workflow_postgres18:/to \
  alpine sh -c 'cd /from && cp -a . /to'
# 再执行上面两条 ALTER，并在 .env 改 DATABASE_URL
```
> ⚠️ 方案 B 属于「异地备份/恢复」同类高风险动作，执行前**先手动备份**（`scripts/linux/backup-all.sh`），
> 并遵守 2026-09-30 事故复盘的纪律：核对分支、核对未跟踪文件、不要在同一窗口里顺手重建镜像。

## 5. 【必做】systemd 单元

单元**文件名**变了，`/etc/systemd/system/` 下要换名并重装：

```bash
cd /opt/knowtrace
git pull            # 先核对在 main 分支、无未跟踪文件挡 pull（见 2026-09-30 复盘）

# 备份单元（deploy/systemd）
sudo systemctl disable --now knowtrace-backup.timer knowtrace-offsite-backup.timer
sudo rm -f /etc/systemd/system/knowtrace-{backup,offsite-backup}.{service,timer}
sudo install -m 644 deploy/systemd/knowtrace-workflow-offsite-backup.service /etc/systemd/system/
sudo install -m 644 deploy/systemd/knowtrace-workflow-offsite-backup.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now knowtrace-workflow-backup.timer knowtrace-workflow-offsite-backup.timer

# 运维修检单元（scripts/ops/systemd）
sudo systemctl disable --now knowtrace-{daily-ops,weekly-check,monthly-ops}.{service,timer}
sudo rm -f /etc/systemd/system/knowtrace-{daily-ops,weekly-check,monthly-ops}.{service,timer}
sudo install -m 644 scripts/ops/systemd/knowtrace-workflow-*.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now knowtrace-workflow-daily-ops.timer knowtrace-workflow-weekly-check.timer knowtrace-workflow-monthly-ops.timer
```

> `scripts/linux/deploy-observability.sh` 与 `scripts/ops/systemd/install.sh` 已同步改为新文件名，
> 走脚本重装也可以（更省事）。

## 6. 【必做】Nginx 站点 / Grafana 面板

```bash
# Nginx 站点
sudo cp -a /etc/nginx/sites-available/knowtrace.conf /etc/nginx/sites-available/knowtrace-workflow.conf
sudo ln -sfn /etc/nginx/sites-available/knowtrace-workflow.conf /etc/nginx/sites-enabled/knowtrace-workflow.conf
sudo rm -f /etc/nginx/sites-enabled/knowtrace.conf /etc/nginx/sites-available/knowtrace.conf
sudo nginx -t && sudo systemctl reload nginx
```
> `scripts/linux/install-observability-nginx.sh` 与 `prepare-host.sh` 已同步新名，走脚本更稳。

Grafana 面板：`docker compose ... up -d grafana` 后，provisioning 会按新文件名与新 uid
`knowtrace-workflow-vps-overview` 重新载入；旧 uid 的面板会自动消失。

1. 手动备份：`scripts/linux/backup-all.sh`
