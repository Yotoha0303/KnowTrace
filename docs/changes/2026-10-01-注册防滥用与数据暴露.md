## 1. 诊断：四个问题，一个净暴露

### 问题 1：注册**没有任何防滥用措施**【实测】

```
注册限流      ← RegisterHandler 里没有任何 limit/check
邮箱验证      ← RegisterRequest 只有 username + password
```

**任何人**可以脚本化批量建号。

### 问题 2：新用户**自动成为默认空间的 member**【依据：文件】

```ts
// src/features/workspace/service.ts:230
export async function ensureLegacyWorkspaceMembership(identity) {
  await db.insert(workspaceMemberships).values({
    workspaceId: LEGACY_DEFAULT_WORKSPACE_ID,      // ← 默认空间
    role: identity.isAdmin ? "owner" : "member",   // ← member
  })
}
```

`resolveActorWorkspace` 每次都会先调它——**新用户首次访问即入默认空间**。

### 问题 3：member **能读 shared**【依据：文件】

```ts
// src/features/auth/resource-scope.ts:8
scope.isAdmin ? 全部 : (createdById == 自己) || (visibility == "shared")
```

### 问题 4：**净暴露 = 2 条真实记录**【实测】

| 空间 | 记录 | 新用户 |
| --- | --- | --- |
| **默认空间** | 大模型训练工具链与 AI 智能体项目构想 | ✅ **可读** |
| | agent业务方向考虑 | ✅ **可读** |
| 测试空间 | 上线测试 / 测试 | ❌ 不可读（非成员） |

> **问题 2 + 3 + 4 串起来才是真正的风险**：
> 单看每一条都是"设计如此"，合起来是**任何注册者能读到用户的真实项目构想**。

## 2. 方案（分档，按代价）

### A 档 —— 零代码，立刻可做

| # | 动作 | 效果 | 代价 |
| --- | --- | --- | --- |
| **A1** | **把默认空间那 2 条记录改为 `private`** | **立刻切断暴露面** | `KnowTraceReviewer` 也读不到这 2 条——但它本来不需要（独立复核只针对 claims） |
| A2 | **关闭注册**（回滚今天的 open） | 最彻底 | 与用户上一轮明确要求冲突，**需用户决定** |
| A3 | edge 层加注册限流 | 防批量建号 | ❌ **不可行**：nginx 1.24 **未编译 `limit_req` 模块**，也无动态模块【实测】 |

### B 档 —— 要改代码 / 加功能

| # | 动作 | 为什么本次不做 |
| --- | --- | --- |
| B1 | 新用户**不**自动加入默认空间 | 会让他们"没有可访问的 Workspace"而报错，**必须配套自建空间** → 是功能改动 |
| B2 | 注册限流 / 邮箱验证 | **新功能**，用户已要求停止 |

## 3. 本次执行什么 / 不执行什么

### 执行 **A1**

**理由**：它与用户「开放注册」的指令**不冲突**——注册继续开着，
只是**把不该被外人看到的内容收回**。

**具体**：把默认空间那 2 条真实记录 `shared → private`。
- 管理员（`go-user:1`）**仍能看**（admin 读全部）
- 非管理员成员**不再能读**
- **可逆**：一行 SQL 即可改回

### **不执行 A2**，但**提请用户决定**

关注册会**反转用户上一轮的明确要求**，我不擅自做。
**但我建议认真考虑它**，理由：

> 当前形态下，开放注册的**收益**（让陌生人建号）很小，
> **成本**（无任何防滥用 + 新用户自动进共享空间）却很大。
> 而且**走通业务流程并不需要开放注册**——`KnowTraceReviewer` 已经建好了。

**若要做真正的多用户**，正确顺序是：**先补 B1/B2 的能力，再开放**。
