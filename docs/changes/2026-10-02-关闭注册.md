# 2026-10-02 关闭自助注册

| 项 | 值 |
| --- | --- |
| 记录时间 | 2026-10-02（**变动前先写**；结果见第 4 节） |
| 用户决策 | 关闭注册（在《可靠注册方案》的四个选项中选 D，并作为后续邀请制的前置） |
| 变动范围 | `/opt/knowtrace/.env` 的 `AUTH_REGISTRATION_ENABLED` |

---

## 1. 为什么关

**昨天实测出的必然暴露**：

> 新用户自动进默认空间 + member 可读 shared +
> **管理员的 `private` 会被 `applyAdminSharingPolicy` 强制改回 `shared`**
> ⇒ **任何注册者必然能读到管理员的全部记录。**

**这不是配置问题，是三个机制叠加的必然结果。**
在邀请制（或任何身份门槛）建好之前，**关闭注册是唯一能立刻消除它的零代码手段**。

## 2. ⚠️ 必须写明的代价：关掉后没有别的建号路径

【实测】认证服务**没有管理员建号接口**：

```text
POST /api/v1/auth/login · refresh · logout
GET  /api/v1/users/me
PUT  /api/v1/users/me/profile
PATCH /api/v1/users/me/update/password
GET  /api/v1/admin/roles · permissions
PUT  /api/v1/admin/users/:id/roles      ← 只能改角色，不能建号
```

**没有 `POST /api/v1/users`。**

所以关掉之后，要再加人只有三条路：

| 路 | 说明 |
| --- | --- |
| A | **临时开一次注册**，建完立刻关（就是今天建 `KnowTraceReviewer` 用过的方式） |
| B | 直接写 `go_user_system.users`（bcrypt 哈希），绕过业务层 |
| C | 等邀请制做好 |

**这意味着"关闭"是可逆的，但不是"零成本可逆"**——每次加人都要一次暴露窗口（或写库）。
**这是关闭注册的真实代价，写在这里以免日后忘记。**

## 3. ⚠️ 这个开关有**两个消费者**（昨天的教训）

```yaml
compose.yaml:103  app:  AUTH_REGISTRATION_ENABLED   ← Proxy 用它决定是否放行 /register
compose.yaml:140  auth: REGISTRATION_ENABLED        ← 认证服务用它决定是否挂载 /auth/register
```

**只重启一侧会让两边不一致**：认证服务关了注册而应用仍放行 `/register`
（或反过来）——表现为「改了却没生效」。
**所以本次两侧都要重建。**

## 4. 执行结果

**填写时间：2026-10-02**

### 4.1 执行

```
AUTH_REGISTRATION_ENABLED  true → false
```

备份 `/root/env.bak-closereg-*`；**两侧都重建**（auth + app，`--no-deps --no-build`）。

### 4.2 验收【实测】

| # | 标准 | 结果 |
| --- | --- | --- |
| 1 | auth 侧容器收到 `false` | ✅ `REGISTRATION_ENABLED=false` |
| 2 | app 侧容器收到 `false` | ✅ `AUTH_REGISTRATION_ENABLED=false` |
| 3 | 认证服务拒绝注册 | ✅ `/api/v1/auth/register` → **404** |
| 4 | 公网注册入口关闭 | ✅ `/register` → **307** 到 `/login?registration=disabled` |
| 5 | 登录不受影响 | ✅ `/login` → **200** |
| 6 | **现有账号仍可用** | ✅ `KnowTrace-Workflow` / `KnowTraceReviewer` 均 **200** |
| 7 | 服务健康 | ✅ auth 200 / app 200 |
| 8 | 应用运行态未变 | ✅ `revision` 仍 `83c7e76` |

**第 6 条最重要**：关闭注册**只影响"建新号"，不影响"已有号"**——
所以走通业务流程（需要 `KnowTraceReviewer`）**不受影响**。

### 4.3 顺带清理：一处我昨天留下的脏数据

昨天删注册探针账号时**没清干净**，`user_roles` 里留了 `user_id=3` 的**孤儿行**
（用户已不存在，角色关系还在）。

**已清理**。当前只剩合法行：

```text
user 1 (KnowTrace-Workflow)          → role 1 (admin), role 2 (user)
user 2 (KnowTraceReviewer)  → role 2 (user)
```

### 4.4 暴露面：已消除

关闭注册后，「任何注册者必然读到管理员记录」这条链路**不再可达**——
因为已经没有注册者了。

**但要写清**：这是**关掉了入口**，不是**修好了机制**。
那三条机制仍然在（新用户自动进默认空间 / member 可读 shared /
管理员 private 被强制改回 shared）。
**邀请制若只做"邀请码"而不做"邀请时指定空间与角色"，暴露会随第一个邀请者回来。**
