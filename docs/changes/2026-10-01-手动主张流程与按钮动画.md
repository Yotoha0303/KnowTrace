## 1. 报告②：按钮上的循环动画 —— 已定位

**先说清一点**：`.button:hover` 的样式**是干净的**——

```css
.button { transition: transform .15s, background .15s, opacity .15s; }
.button:hover:not(:disabled) { transform: translateY(-1px); }
```

**没有任何 `:hover` 带 animation**（全文件扫描确认）。所以不是 hover 本身触发动画。

**真正的原因**：按钮上的 spinner 只在 `isPending` 时渲染：

```tsx
{isPending ? <LoaderCircle className="processing-spinner" size={15} /> : <Save size={15} />}
```

而 `isPending` 来自 `useTransition`，**提交处理把 `router.refresh()` 放在了 transition 回调里**：

```tsx
startTransition(async () => {
  const result = await createManualClaimAction({...});
  ...
  setMessage("主张已保存为候选，可继续开始调查和补充证据。");
  router.refresh();          // ← 在 transition 内
});
```

**后果**【推断，机制清晰但未在浏览器实测】：`isPending` 要等 **Server Action + `force-dynamic` 页面重渲染**两件事都完成才收敛。而那是一次完整服务端往返（实测该页 0.13s，加上重渲染更久）。表现就是**按钮持续转**——用户看到的「循环刷新的动画」。

**判定**：pending 的语义被扩大了。它**应该**表示「提交动作在进行」，却被拽上了「页面在刷新」。两者必须分开。

## 2. 报告①：流程不清晰 —— 已定位

**【实测】实际流程**（读 `claim-workflow-panel.tsx` 的条件渲染）：

```text
1. 填「手动添加主张」表单 → 保存为 candidate
2. 主张出现在列表，操作区出现「开始调查」/「撤回」
3. **必须点「开始调查」** → status 变为 investigating
4. 只有此时，第 620 行 `claim.status === "investigating"` 才为真
   → 「添加证据」表单才出现
```

**问题**：第 3 步是**硬前置**，但**界面上没有任何地方说明**。

保存后的提示是：

> 「主张已保存为候选，可继续开始调查和补充证据。」

——它把「开始调查」和「补充证据」并列说了，**没告诉你后者依赖前者**。
用户存完主张去找「添加证据」，**找不到**（因为表单还没渲染）。

### 这不是文案小瑕疵

它让一个**有顺序要求的流程**看起来像**两个并列入口**。
用户会以为证据可以独立于调查添加。

### 5.2 ⚠️ 一次证伪：我的回归测试有一条是无效的

我为「按钮转不停」写了测试，并**实测它在旧代码上是否失败**——这是必要的一步，
否则会留下一条「看起来守着一个 bug、实际抓不到」的测试。

| 测试 | 在**原始代码**上 | 判定 |
| --- | --- | --- |
| ① 按钮等待态 | **通过** | ❌ **无效 —— 抓不到它名义上要守的 bug** |
| ② 文案（并列 vs 前置） | **失败**（`expected <p class="form-success"> to be null`） | ✅ **有效，真回归测试** |
| ③ 失败后按钮可用 | 通过 | 有效但非承重 |

**①为什么无效**：原版里 `router.refresh()` **并未被 await**，它保持 pending 靠的是
**Next 路由自身的状态**，而 mock 的 `useRouter` **复现不了**。

**处置**：把①的**文档注释改为诚实描述**（说明它抓不到、只验证「提交后按钮回正常态」），
并**在测试文件头写明**：**②「按钮转不停」没有自动化测试覆盖，只能靠浏览器确认。**

**为什么保留而不是删掉**：它仍验证「提交结束后按钮回到正常态」；
删掉会连带失去那部分覆盖。但**必须标明它不是承重的**——
一条被误认为守护了某缺陷的测试，比没有测试更危险。

### 5.3 途中我也查错了一次

第一次做证伪时，我把代码改回同步的 `startTransition(() => router.refresh())`，
测试**仍然通过**，我一度以为测试无效。**那次还原不忠实**：
`startTransition(async () => {...})` 会保持 pending 到 promise 结算，而同步版不会。
用 **git 原始版本**重做后，才得到上表的真实结论。见 5.4。
