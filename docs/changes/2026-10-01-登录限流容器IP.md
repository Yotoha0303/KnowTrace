## 1. 要修什么

**现象**：即使账号密码正确，仍可能被拒。

**根因**【实测】：登录限流按 IP 计数，而认证服务看到的 IP 是**应用容器地址**，
导致**所有用户共用一个限流桶**。任一来源累计失败 20 次，
**全站所有人 15 分钟内都登不进去**。

---

## 2. 断层定位（三层，逐层实测）

```text
真实客户端 172.96.141.83
   ↓ Caddy（自动设 X-Forwarded-For）
nginx                        ← ✅ 能拿到真实 IP
   ↓ proxy_set_header X-Forwarded-For $http_x_forwarded_for   ← ❌ 转发的是**入站头**
应用容器 (172.18.0.9)        ← ❌ 收不到真实 IP
   ↓ loginWithGoUserSystem() 不带任何 XFF                     ← ❌ 完全不转发
认证容器 (172.18.0.3)
   ↓ Gin c.ClientIP()，而 trustedProxies: []                  ← ❌ 谁都不信 → 取 RemoteAddr
最终记到 172.18.0.9
```

**逐层证据**：

| 层 | 证据 |
| --- | --- |
| nginx 能拿到真实 IP | `/var/log/nginx/knowtrace.access.log` 里非探针请求首列是 `172.96.141.83`（50 次登录） |
| 我伪造 XFF 无效 | 带 `X-Forwarded-For: 203.0.113.77` 请求，nginx 仍记 `45.64.74.99` → **Caddy 覆盖不可信 XFF，链路可信** |
| 认证侧收到的是容器 IP | `docker logs knowtrace-auth-1`：`"client_ip":"172.18.0.9"` |

## 3. 关键发现：机制早就有了，就差一个值

**【实测】** 侦查时发现三处已有的接线：

| 位置 | 内容 |
| --- | --- |
| `services/go-user-system/config/config.go:478` | `if v := os.Getenv("TRUSTED_PROXIES"); v != "" { cfg.HttpServer.TrustedProxies = splitCommaSeparated(v) }` |
| `compose.yaml:107` | `TRUSTED_PROXIES: ${AUTH_TRUSTED_PROXIES:-}` |
| `.env:13` | `AUTH_TRUSTED_PROXIES=` ← **空值** |

**所以：机制写了、compose 的线也接了，唯独 `.env` 里的值是空的**，
容器收到空串 → 回落到 `config.yml` 的 `trustedProxies: []`。

**这正是本项目反复出现的那个形态**（生态观察 F-04、tech-review S-2 同源）：
**「接线完成」不等于「电流通过」。**

---

## 4. 改动方案（三层，缺一不可）

| # | 改动 | 为什么不能只改这一处 |
| --- | --- | --- |
| a | **nginx**：`X-Forwarded-For $http_x_forwarded_for` → **`$remote_addr`** | 转发**入站头**是错的；真实客户端在 `$remote_addr`（Caddy 已用 XFF 还原过） |
| b | **BFF**：把真实客户端 IP 作为 `X-Forwarded-For` 转发给认证服务 | 否则 (a) 拿到的 IP 到不了认证层 |
| c | **`.env`**：`AUTH_TRUSTED_PROXIES=172.18.0.0/16` | 否则认证侧的 `trustedProxies: []` 会**忽略** XFF，前两步白做 |

**为什么 c 用整个子网而不是单个 IP**：应用容器 IP 由 Docker 动态分配，
只信任单个 IP 会在重启后**静默失效**。`172.18.0.0/16` 是 compose 的私有网络，
其中只有本项目自己的容器。

**残余风险（写明）**：该网络内的**任何**容器都能伪造 XFF 绕过 IP 维度限流。
考虑到该网络不含外部方，且账号维度（`accountLimit: 5`）仍然生效，**接受**。

---

## 5. 明确不做

| 不做 | 原因 |
| --- | --- |
| **只加 XFF 而不配 `trustedProxies`** | 会**信任客户端伪造的头**，可用来绕过限流——比现状更糟 |
| **去掉 IP 维度限流** | 账号维度挡不住「一个 IP 猛撞很多账号」；两个维度各有用途 |
| **改 `config.yml`** | 它是 `services/go-user-system/` 里**被跟踪**的文件，改它会与 Git subtree 上游分叉。环境变量覆盖是正确入口 |
