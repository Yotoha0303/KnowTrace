## 3. 关键约束：新密码**不能进会话记录**

这是本次做法与常规不同的地方。

**如果我用工具生成密码再告诉他，新密码就落进了会话记录——轮换等于原地打转。**
所以流程设计为：

```text
在服务器本地生成（openssl rand）
  → 直接写入目标（改密接口 / grafana-cli --password-from-stdin）
  → 只把「成功/失败」回传
  → 落盘到一个 600 的文件，用户自己去读
```

**全程新密码不经过模型上下文，不出现在任何命令参数里。**

## 5. 新密码在哪 / 怎么处理

**位置**：`/root/knowtrace-credentials-20261001.txt`（权限 `600`，仅 root 可读）

```bash
ssh -p 22345 root@<VPS> 'cat /root/knowtrace-credentials-20261001.txt'
```

**建议**：把它读进你的密码管理器，然后**删掉这个文件**：

```bash
ssh -p 22345 root@<VPS> 'shred -u /root/knowtrace-credentials-20261001.txt'
```

**为什么文件是 600 且只在服务器**：这是「不让新密码进会话记录」这一约束的必然结果。
它不是长期的凭据存放方案——**长期方案是你自己的密码管理器**。
