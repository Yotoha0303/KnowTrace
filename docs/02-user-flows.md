# 用户流程

## 1. 打开应用

```text
打开首页
→ 服务端读取最近 Capture 和可用 Category
→ 页面显示快速输入框和最近记录
→ 不出现登录或注册页面
```

部署边界提示：应用首次运行时应明确说明“当前没有应用内访问控制，只适合可信环境”。

## 2. 快速记录

```text
输入关键词或想法片段
→ 可填写描述对象，发生时间默认当前时间且可调整
→ 点击保存/使用快捷键
→ 客户端生成幂等键
→ Server Action 校验输入
→ Service 创建 Capture
→ 数据库提交
→ 页面显示新记录
```

关键要求：

- 保存前不要求标题、类型和分类。
- 描述对象不要求预先建档；同一公司或人物可以直接按名称填写。
- 浏览器把本地日期时间转换为 ISO 时点提交，服务端统一保存 UTC。
- 保存失败时输入内容保留在浏览器。
- 相同幂等键与相同内容重试只产生一条记录。
- 保存成功后可选择“AI 整理”，但不自动强制调用。

## 3. 手动分类

```text
打开 Capture
→ 选择 Content Type
→ 选择已有 Category 或创建 Category
→ 提交分类变化
→ 服务端幂等更新关系
```

分类与正文编辑分开提交，避免仅修改 Category 就产生正文 Revision。

## 4. AI 整理

```text
Capture 已保存
→ 点击“AI 整理”
→ 创建 running AI Run
→ 服务端调用配置的 Provider
→ 校验结构化响应
→ 成功：保存 Suggestion 并将 Run 设为 succeeded
→ 失败：保存错误分类并将 Run 设为 failed
```

首版允许一次 HTTP 请求等待模型结果，但必须设置超时。未来调用量或时长增加后，再迁移到持久化任务 Worker。

## 5. 处理 AI 建议

建议页面并排展示：

```text
左侧：用户原始记录
右侧：AI 处理阶段、候选标题、摘要、少量分类、局部原文建议、语义单元和待补充问题
```

操作：

- 全部接受。
- 仅接受选中的标题/类型/分类。
- 修改后接受。
- 拒绝。

处理规则：

- 接受标题或类型会创建 Capture Revision 并增加版本；接受分类只更新分类关系。
- AI 摘要与语义单元保存在 Suggestion 中。
- AI 只能提供带有原文定位的局部修改建议，默认不选；用户逐条勾选后才写回正文并创建 Revision。
- AI 分类候选合计最多 3 个、新分类最多 1 个且默认不选；再次接受时替换旧 AI 分类，保留手动分类。
- 如果当前 Capture 版本不同于来源版本，必须先提示过期。

## 6. 编辑与版本冲突

```text
打开 Capture v1
→ 编辑正文
→ 提交 expected_version=1
→ 保存 v1 到 Revision
→ Capture 更新为 v2
```

如果另一个页面已经更新为 v2：

```text
返回 CAPTURE_VERSION_CONFLICT
→ 保留当前编辑内容
→ 显示服务器最新版本
→ 使用者手动决定如何合并
```

首版不实现自动文本合并。

## 7. 候选主张与证据来源检查

```text
AI 候选（默认不选）
→ 人工创建 candidate Claim
→ 开始调查
→ 添加 unreviewed Evidence
→ 检查公共 HTTP(S) 来源并保存快照
→ 摘录匹配后人工采纳或排除
→ 至少一条已采纳证据后提交 ready_for_review
→ 选择支持 / 反驳 / 证据不足并填写依据与限制
→ 冻结证据快照，进入 concluded
```

来源检查失败或摘录不匹配时保留检查结果与错误码，Evidence 不能采纳，但可以重新检查或人工排除。结论后仍可重新调查，旧结论保留。任何状态都不用 `verified` 简化当前证据边界。

任一未撤回 Claim 都可以主动运行 AI 可靠性审查。系统冻结当时有效的采纳证据输入，AI 提示覆盖、正反平衡和待补检查，但不改变上述流程的任何状态。Claim 或有效证据变化后，旧审查仍可回看并显示“输入已变化”。

## 8. 归档与恢复

```text
active Capture → archive → archived
archived Capture → restore → active
```

Category 也支持相同的归档与恢复。Capture 可以在二次确认后永久删除；删除会级联移除 Revision、分类关系、AI Run 和 Suggestion，Category 本身不会因此删除。

## 9. 小群体使用

所有访问者共享同一数据集，系统不能区分操作者身份。因此：

- 不能提供可靠的“谁修改了内容”。
- 不能保存对其他成员私密的记录。
- 不能给不同成员配置分类或访问权限。
- 应通过局域网、VPN、反向代理访问策略等方式控制谁能打开应用。

一旦出现成员级隔离或审计需求，身份与权限将成为单独里程碑，而不是在现有字段中伪造用户名。

## 10. 统一检索与主题回看

```text
输入不完整关键词
→ 可选知识对象、Category、描述对象和发生日期范围
→ 服务端分别检索原始记录、主张、证据和人工结论
→ 按知识对象分组展示状态与命中上下文
→ 回到来源 Capture 查看完整证据链
```

从 Category 进入时，主题档案先展示聚合指标和最新人工结论，再展示来源记录。它是实时只读投影，不创建新的“事实”副本，也不让 AI 自动合并不同证据边界的结论。

普通全文词会检索 Capture 的标题、描述对象和正文。描述对象筛选采用部分匹配；发生日期筛选使用 `occurred_at`，不是 `created_at`，结束日期包含当天 24 小时。
