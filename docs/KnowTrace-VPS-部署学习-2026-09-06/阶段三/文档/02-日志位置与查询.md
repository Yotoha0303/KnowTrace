# 阶段三日志位置与查询

## 结论

阶段三没有把日志集中到一个“万能文件”。边缘代理、Docker 服务、故障演练和 ELK 数据各有权威位置；排障时按请求链路从外到内查询。

## 边缘与系统日志

| 对象 | 位置/命令 | 用途 |
| --- | --- | --- |
| Caddy access | `/var/log/caddy/knowtrace-access.log` | TLS 边缘请求、状态码、来源 |
| Caddy 服务 | `journalctl -u caddy --since "30 min ago"` | 证书、监听、代理错误 |
| Nginx access | `/var/log/nginx/knowtrace.access.log` | 反代请求与状态码 |
| Nginx error | `/var/log/nginx/knowtrace.error.log` | upstream、超时、配置错误 |
| Nginx 服务 | `journalctl -u nginx --since "30 min ago"` | reload/start 结果 |
| SSH | `journalctl -u ssh --since "30 min ago"` | 管理入口和认证问题 |

## Docker 服务日志

```bash
docker logs --since 30m knowtrace-app-1
docker logs --since 30m knowtrace-auth-1
docker logs --since 30m knowtrace-prometheus-1
docker logs --since 30m knowtrace-alertmanager-1
docker logs --since 30m knowtrace-grafana-1
docker logs --since 30m knowtrace-blackbox-exporter-1
docker logs --since 30m knowtrace-node-exporter-1
```

按需 ELK 运行时：

```bash
docker logs --since 30m knowtrace-elasticsearch-1
docker logs --since 30m knowtrace-logstash-1
docker logs --since 30m knowtrace-kibana-1
```

阶段三新建容器使用 Docker `json-file`，每个文件最大 10 MB、最多 3 个。不要直接修改 `/var/lib/docker/containers` 中的 JSON 文件。

## 故障演练日志

本次真实日志：

```text
/var/log/knowtrace-observability-drill-20260908T044604Z.log
权限：0600 root:root
结果：RESULT=PASS
```

查询：

```bash
sudo less /var/log/knowtrace-observability-drill-20260908T044604Z.log
sudo grep -E 'PASS|FAIL|ACTION|RESULT' /var/log/knowtrace-observability-drill-*.log
```

## Prometheus 与 Alertmanager 证据

```bash
curl -fsS http://127.0.0.1:9090/api/v1/targets
curl -fsS http://127.0.0.1:9090/api/v1/alerts
curl -fsS http://127.0.0.1:9093/api/v2/alerts
```

这些是运行状态 API，不等于持久日志。查询配置或问题时还要查看相应容器日志。不要把 metrics Bearer token 写进命令历史；优先运行项目验收脚本。

## ELK 索引

- 索引：`knowtrace-logs-YYYY.MM.dd`
- Data view：`knowtrace-logs-*`
- ILM：`knowtrace-logs-7d`
- 数据卷：`knowtrace_elasticsearch_data`、`knowtrace_logstash_data`、`knowtrace_kibana_data`

```bash
scripts/linux/elk.sh up
curl -fsS 'http://127.0.0.1:9200/_cat/indices/knowtrace-logs-*?v'
scripts/linux/elk.sh stop
```

ELK 当前是停止状态；停止不会删除数据卷。不要为了排障运行 `docker compose down --volumes`。

## 推荐排障顺序

1. 保存时间、URL、状态码和影响范围。
2. 验证公网 DNS/TLS，再看 Caddy。
3. 看 Nginx access/error，确认请求是否到 upstream。
4. 看 app/auth 容器日志和 ready。
5. 看 Prometheus target、告警和 Alertmanager。
6. 仅在资源足够时启动 ELK做集中检索。
7. 恢复后再次验证公网 ready、12/12 targets 和告警清除。

任何记录都要删除密码、Authorization、Cookie、Token 和完整 `.env`。
