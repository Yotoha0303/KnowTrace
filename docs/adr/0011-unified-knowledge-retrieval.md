# ADR-0011：先建立可追溯的统一检索读模型

- 状态：accepted
- 日期：2026-08-22

## 背景

KnowTrace 已能保存 Capture、Claim、Evidence 和 ClaimReview，但这些对象分散在记录详情、分类页和主张库。用户通常只记得一个关键词或场景，不一定知道它属于哪个实体。直接进入向量检索或 AI 问答，会放大来源混淆，也难以说明答案来自原文、未审核证据还是人工结论。

## 决策

新增统一知识检索读模型和分类主题档案：

- 检索覆盖 Capture 标题/正文、Claim 陈述/原文/证伪条件、Evidence 标题/摘录/备注、ClaimReview 依据/限制。
- 结果按实体类型分组并显示状态、分类、来源记录回链，绝不把普通命中包装成“已验证知识”。
- 分类页聚合记录、主张、有效采纳证据和最新人工结论，作为主题档案的首个版本。
- 当前个人/小群体规模使用 PostgreSQL `pg_trgm` 支持中文子串和模糊片段索引；查询长度和每类返回量保持有界。
- 检索层只读，不改变 Claim、Evidence、Review 或 AI 状态。

## 结果

用户可以从不确定线索回到完整来源链，后续相似记录、主题 AI 总结和 RAG 可以复用同一读模型。代价是数据库需要可启用 `pg_trgm` 扩展；若部署平台不允许创建扩展，需要由数据库管理员预先启用。

## 暂不采用

- 不使用简单“全文答案”替代分组结果，因为它会抹平证据状态。
- 不在本阶段引入向量数据库；当前数据量和中文关键词回看尚不足以证明额外复杂度。
- 不缓存主题档案；个人规模下先保持从事实表实时读取，等实际性能数据再决定投影表或缓存。
