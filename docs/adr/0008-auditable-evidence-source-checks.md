# ADR-0008：证据采纳前进行可审计的来源完整性检查

- 状态：accepted
- 日期：2026-08-15

## 背景

P1.1 要求 Evidence 保存 URL 和摘录，但系统无法证明该 URL 当时可以访问，也无法确认摘录是否真的存在于页面。仅依赖用户点击链接会产生不可审计的人工步骤；直接让服务端抓取任意 URL 又会引入 SSRF。

## 决策

1. Evidence 默认来源状态为 `unchecked`，不能直接采纳。
2. 来源检查只抓取公共网络上的标准端口 HTTP(S) HTML/纯文本内容。
3. DNS 返回的所有地址必须为公共地址，请求固定到已校验 IP；每个重定向目标重新执行相同校验。
4. 限制重定向次数、响应头、响应体（1 MB）与总等待时间，不发送 Cookie、凭据或压缩协商。
5. 每次检查新增不可变 EvidenceSourceCheck，保存最终 URL、HTTP 状态、类型、SHA-256、页面标题、响应字节数、时间和摘录匹配结果。
6. 只有最新检查成功且摘录匹配的未审核 Evidence 才能被人工采纳；人工排除不要求检查。

## 边界

来源检查只证明：在该检查时间，系统安全抓取到一份内容，且规范化后的正文包含用户保存的摘录。它不证明作者身份、来源权威性、页面长期不变、证据立场正确或 Claim 真实。

## 影响

- Evidence 的来源完整性从界面提示升级为服务端不变量。
- 内容哈希可以用于后续检测来源变化，但当前不保存完整网页副本。
- 某些非标准端口、登录后页面、PDF、JavaScript 动态渲染页面暂时无法自动检查；用户仍可保存并排除这类 Evidence，但不能将其采纳为通过门槛的证据。
