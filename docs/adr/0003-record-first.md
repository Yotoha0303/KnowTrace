# ADR-0003：P0 记录优先，延期知识验证和 RAG

- 状态：superseded（由 ADR-0005 替代）
- 日期：2026-08-14

## 背景

长期产品需要事实核查、证据、可证伪主张、严格状态流转和系统化输出，但用户当前决定先完成最小实现，以记录为主，展示和筛选后续再增强。

## 决策

原决策要求 P0 实现身份、Workspace、Capture、Revision、归档和最小时间线，P1 再实现 AI 整理。用户随后移除了身份与 Workspace，并将分类和 AI 处理提升为 P0，详见 ADR-0005。以下延期能力仍然有效：

- Claim/Evidence/Review 工作流。
- 已验证知识发布。
- 向量检索和 RAG。
- 高级筛选和知识图谱。
- 原生 App。

## 原因

- 先验证用户是否会持续记录。
- 先建立可靠、可追溯的数据入口。
- 避免在没有数据时过度设计知识本体和检索。

## 后果

正面：

- 更早获得可用版本。
- 研发风险集中在基础工程质量。
- 后续验证流程可以建立在真实记录样本上。

代价：

- P0 看起来更像记录工具，AI 差异化需要在 P1 才出现。
- 必须坚持不用“可信知识库”描述未经验证的 Capture。

## 进入 P1 的条件

- P0 主流程稳定。
- 已积累足够的真实关键词和想法片段样本。
- 可以从样本中定义 AI 输出 Schema 和验收数据集。
