# ADR-0015：按创建者隔离业务数据

- 状态：accepted
- 日期：2026-08-23
- 扩展：ADR-0013、ADR-0014

## 背景

接入登录后，KnowTrace 仍只有共享数据域：任何已登录成员都能读取全部记录。项目开始面向个人和小群体使用后，仅认证而不做资源授权会造成成员间内容泄露。

## 决策

- Capture 与 Category 保存 go-user-system 用户 ID 派生的 `created_by_id` 和创建时显示名快照。
- `admin` 角色拥有实例级全局数据范围；普通成员只拥有 `created_by_id` 与本人匹配的数据范围。
- Revision、AI Run、Suggestion、Claim、Evidence、图片、主题综合和发布版本通过 Capture 或 Category 继承访问边界，不重复保存可漂移的所有者字段。
- 列表、详情、搜索、统计、对象时间线、相似记录、导入导出、图片和全部写操作都在服务端数据访问层校验，前端隐藏不作为安全边界。
- 跨成员资源按不存在处理，避免通过 UUID 猜测确认资源存在。
- 历史无身份数据迁移为 `legacy-local`，只允许管理员访问。
- 幂等键和分类规范化名称改为创建者内唯一，避免成员之间因相同输入互相冲突。

## 后果

- 管理员可以查看和管理所有成员内容；管理员权限必须谨慎分配。
- 普通成员之间默认完全隔离，当前不支持主动共享、Workspace 或组织级协作。
- 新增任何读写入口必须从认证后端重新取得可信角色，并复用相同的数据范围规则。
- 删除 go-user-system 用户不会自动删除其业务内容；内容仍保留创建者标识并可由管理员处理。
