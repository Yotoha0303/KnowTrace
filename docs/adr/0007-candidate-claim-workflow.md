# ADR-0007：以候选主张和证据门槛扩展可靠性流程

- 状态：accepted
- 日期：2026-08-15

## 背景

Capture 和 AI Suggestion 已能可靠记录输入与整理过程，但它们都不能表达“这句话是否可以被外部证据支持或反驳”。直接增加 `verified` 字段会隐藏来源、反例、审核过程和版本差异，也会让 AI 建议看起来像事实结论。

## 决策

增加独立 Claim 与 ClaimEvidence 模型，并只实现到待审核为止的最小流程：

1. AI 每次最多提出 3 个可证伪主张候选，候选默认不选。
2. 用户明确接纳后创建 `candidate` Claim，绑定 Capture 版本、来源片段和证伪条件。
3. Claim 使用 `candidate → investigating → ready_for_review` 状态机；活动状态可撤回，待审核可退回调查。
4. Evidence 必须保存 HTTP(S) 来源、标题、摘录和支持/反驳/背景立场，默认未审核。
5. 只有人工采纳的 Evidence 计入提交门槛；至少一条后才能进入 `ready_for_review`。
6. 当前不提供 `verified` 状态或按钮，`ready_for_review` 不表示真实。

## 原因

- 将“原始记录”“AI 推测”“可证伪陈述”“证据”和“审核状态”明确分离。
- 先验证用户是否会持续使用证据调查，再投入联网搜索和完整发布闭环。
- 状态与门槛由服务端执行，不能通过前端绕过。

## 影响

正面影响：

- 主张拥有可追溯来源与明确证伪条件。
- 支持证据和反驳证据可以同时存在。
- AI 无法直接宣布内容可靠。

代价与限制：

- 证据来源和摘录目前由人工录入，系统尚未验证网页内容或来源权威性。
- 没有用户系统，当前无法记录审核者身份或职责分离。
- 最终真实性结论、Claim 版本和可靠知识发布仍需独立设计。

## 后续修订

2026-08-22：Evidence 的来源 URL 改为记录时可选。无链接 Evidence 可以先保存，并在至少上传一张图片后走独立的 `manual_attachment` 核验路径：使用者必须在线查看附件并显式确认摘录一致，系统冻结 Evidence 版本、附件清单、SHA-256 组合哈希、确认说明和时间。上传图片本身不等于核验；编辑或新增图片会使旧核验失效。核验通过后仍需单独采纳，原有证据门槛没有被删除。当前确认不包含审核者身份，身份化的小群体职责分离仍需后续决策。
