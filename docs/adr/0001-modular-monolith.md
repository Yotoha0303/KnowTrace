# ADR-0001：使用模块化单体

- 状态：superseded（由 ADR-0004 替代）
- 日期：2026-08-14

## 背景

产品处于需求验证期，服务个人和小型群体，最初方案包含 Workspace 隔离和独立 Go API。后续决策移除了身份与 Workspace，并选择 Next.js 全栈实现。

## 决策

原决策是使用 Go 模块化单体。保留“单体和清晰业务边界”的原则，但具体 Go API 技术方案由 ADR-0004 的 Next.js 全栈单体替代。

## 原因

- 支持本地事务，降低数据一致性复杂度。
- 部署和调试成本低。
- 业务模块仍有清晰边界。
- 将来可以根据真实压力拆出 AI Worker，而不是提前猜测。

## 后果

正面：

- 更快形成可运行产品。
- 更容易编写端到端和集成测试。
- 个人可以维护完整系统。

代价：

- 必须通过代码评审防止模块间随意访问内部数据。
- 单体内部仍需要明确依赖方向。

## 复查条件

- AI 任务明显影响 API 延迟。
- 模块需要独立伸缩或发布。
- 出现独立团队边界或合规隔离要求。
