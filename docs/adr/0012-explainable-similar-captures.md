# ADR-0012：先用可解释的本地信号发现相似记录

- 状态：accepted
- 日期：2026-08-22

## 背景

KnowTrace 已能统一检索和按分类回看，但用户再次遇到相同对象或场景时，仍需要主动想起关键词。直接引入向量库或让 AI 自动建立关系，会增加运行成本、难以解释命中原因，也可能把文字接近误写成事实关联。

## 决策

- 在 Capture 详情页提供只读的相似记录列表，最多显示 5 条并回链原记录。
- 候选信号限定为同一描述对象、共同 Category 和 PostgreSQL `pg_trgm` 文字相似度。
- 使用 GiST trigram 索引进行有界近邻候选查询，再用固定权重排序；同一对象可以独立入选，只有共同分类时还必须存在最低文字重合。
- 每条结果显示命中原因，并固定声明“相似不代表观点一致、内容真实或已经验证”。
- 不保存相似边、不修改 Capture、Claim、Evidence 或 Review 状态。

## 结果

用户可以在阅读当前记录时发现过去的同类场景，并理解系统为什么推荐。结果会随记录内容、对象和分类实时变化，因此不是永久知识关系。新增 GiST 索引会增加少量写入和存储成本。

## 暂不采用

- 不引入向量数据库、Embedding 队列或 RAG。
- 不让 AI 自动合并记录或生成事实关系。
- 不显示无解释的单一综合分数；分数只用于内部排序。
